# 用户增长决策中枢（G-1）

> 详细 UI Spec 见 [09-g1-growth-hub.md](../04-dashboards/09-g1-growth-hub.md)。本文聚焦"决策中枢"的产品策略。

## 一、决策中枢的 6 大组成

```
1. 增长循环健康度（按产品）
2. 用户分层迁移（桑基）
3. 增长瓶颈识别（AI 自动）
4. 增长机会卡片
5. 在跑实验 + 增长动作库
6. 用户全景画像入口
```

## 二、增长瓶颈识别（AI 自动）

```
触发：每日 06:30 自动跑
   ↓
对每条增长循环算"瓶颈得分"
   = (当前转化率 / 行业基准) × (规模因子) × (业务价值因子)
   ↓
得分最低的 3 项 = TOP 3 瓶颈
   ↓
AI 生成"现状 + 基准 + 提升空间 + 推荐动作"
   ↓
推送给增长负责人
```

## 三、增长机会卡片

```
触发条件多源：
  · 智能洞察发现高潜分群
  · 历史 Playbook 复盘发现可复用机会
  · AI 检测到"高价值低触达"群体
  · 季度 OKR 进度落后触发探索
   ↓
每条机会包含：
  · 特征描述
  · 预测潜力（ARR / 用户数）
  · 推荐动作（关联 Playbook）
  · [一键发起实验]
```

## 四、增长动作库（Playbook 库）

- 32 个 Playbook 卡片（37 个 Playbook 中筛选与增长直接相关的）
- 按类型分类：激活 / 留存 / 扩张 / 召回
- 显示：ROI 等级 / 适用产品 / 最近 ROI 实绩
- 点击启动

## 五、增长 OKR 落地

```
公司年度增长 OKR
   ↓
拆解到三产品线
   ↓
每条线拆到增长循环
   ↓
每个循环对应 N 个 Playbook
   ↓
每个 Playbook 持续运行 + AB 验证
   ↓
季度复盘
```

## 六、增长团队组织建议

- **增长负责人**：1 人，对全公司增长 OKR 负责
- **产品线增长 PM**：每产品线 1 人
- **运营**：执行 Playbook、设计 Journey
- **数据 PM**：增长指标定义与 AB 实验设计

## 七、关键产品规则

| 规则 | 说明 |
|---|---|
| 增长动作必须实验 | 不允许"拍脑袋全量上" |
| 每个 Playbook 有 Owner | 季度审计 ROI |
| 实验结果归档决策追溯 | 形成"组织增长方法论" |
| 跨产品增长机会优先 | 复用客户 LTV 最高 |
| 高 NPS 用户优先复用 | 推荐裂变 ROI 最高 |
