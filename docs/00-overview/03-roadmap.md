# 产品路线图

## 阶段划分（按价值，不按时间）

### 阶段 0 · 根基筹备

**目标**：让团队达成共识、定义规范、跑通最小数据通路。

| 任务 | 交付物 |
|---|---|
| 数据治理委员会成立 | 委员会章程 + 评审流程 |
| 埋点规范、命名规范、OneID 方案 | 规范文档 |
| 技术选型确认 | 见 02-architecture/02-tech-stack.md |
| 团队组建 | 中台 PM 3-5 人 + 后端 5-8 + 前端 5-8 + 数据 5-8 + 运营 3-5 |

### 阶段 1 · MVP（让你和高管先用）

**目标**：3 件杀手锏让中台立即产生可见价值。

| 交付物 | 优先级 |
|---|---|
| S-1 产品组合矩阵看板 | P0 |
| `<UserProfile360 />` 嵌入组件 | P0 |
| 决策助理 L1-L3 | P0 |
| 决策追溯库（手动登记） | P0 |
| OneID + 指标平台基础 | P0 |
| 平台业务"询盘 → 报价"链路埋点（试点） | P0 |

**成功标准**：你和 ≥ 5 位高管每周使用 ≥ 3 次。

### 阶段 2 · V1（让业务方接入）

**目标**：扩展到三产品线，跑通业务方接入闭环。

| 交付物 |
|---|
| 智能洞察引擎 V1（异动检测 + 简单归因） |
| 决策助理 L4 + 企微 Bot |
| 8 个 P0 Playbook 上线 |
| 嵌入组件扩展至 5 个 |
| OpenAPI v1 上线，2-3 个业务系统接入 |
| 三产品线全部接入埋点 |

**成功标准**：≥ 5 个业务系统接入；用户运营效率提升 ≥ 20%。

### 阶段 3 · V2（业务模型与战略层）

**目标**：让中台成为公司决策入口。

| 交付物 |
|---|
| 3 套业务模型看板（B-1/B-2/B-3）全部上线 |
| S-2 战略健康度、S-3 PM 效能、S-4 战略假设、S-5 决策待办池 |
| 智能洞察引擎 V2（LLM 归因 + 决策建议） |
| 决策助理 L5 |
| 剩余 22 个 Playbook 上线 |
| 决策追溯库自动复盘 |
| 跨产品分析 5 个场景 |

**成功标准**：全公司每月 ≥ 200 个决策登记；ROI ≥ 5x。

### 阶段 4 · V3（智能化飞跃）

**目标**：从"工具"升级为"AI Agent"。

| 交付物 |
|---|
| 决策助理 L6 主动洞察 |
| 自适应学习引擎 |
| 跨产品分析全部 10 场景 |
| 对话式 BI 全面替代传统看板 |
| 决策方法论自动沉淀报告 |

**成功标准**：助理日活高管 ≥ 80%；ROI ≥ 10x；中台成熟度达到 L5。

## 优先级矩阵

| 优先级 | 定义 |
|---|---|
| P0 | MVP 必须，做不到中台无法上线 |
| P1 | V1 必须，影响业务方接入意愿 |
| P2 | V2 必须，影响中台完整度 |
| P3 | V3 可选，影响中台先进性 |

## 风险与缓解

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 业务方不愿接入 | 中台沦为摆设 | 高管 OKR 联动 + 接入大使制度 + 提供咨询式服务 |
| 数据信任崩塌 | 指标口径冲突 | 指标平台一元化 + 数据治理委员会季度评审 |
| AI 失控 | 误导决策 | 二次确认 + 决策人拍板 + 置信度透明 |
| 数据合规 | 法务风险 | 上线前 PIA 评估 + 行级 + 字段级权限 |
| 微前端冲突 | 嵌入页面破相 | wujie + Shadow DOM 隔离 + CSS 变量主题 |
| 技术债积累 | 长期维护成本 | 季度技术债清理日 + 架构评审机制 |
