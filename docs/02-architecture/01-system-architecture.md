## 二、对外三种集成方式

| 方式 | 形态 | 适用场景 |
|---|---|---|
| **① 数据上报 SDK** | Java SDK + Vue3 SDK | 业务系统埋点上报 |
| **② 业务消费 API** | RESTful + WebSocket + OpenAPI 3.0 | 业务系统查询指标、拉标签、触发分群 |
| **③ 嵌入式 SDK** | Vue3 组件库 + 微前端子应用（wujie） | 业务系统直接嵌入"看板/分析页/触达配置页/用户画像组件" |

## 四、核心架构原则

### 1. 采集服务无状态
- 单 Pod ≥ 1 万 events/s
- 只做轻量校验和入队，不写存储
- HPA 弹性扩缩

### 2. 异步落盘
- 业务高峰不打挂分析系统
- Kafka 缓冲，Flink 流处理

### 3. 指标平台一元化
- 所有指标只在指标平台定义
- 所有应用走指标平台查询
- 杜绝口径漂移

### 4. OneID 实时打通
- 设备 ID / 账号 ID / 企业 ID 映射常驻 Redis
- 采集时实时打通，避免离线对齐误差

### 5. 微服务边界（DDD 限界上下文）
- 初期合并为 3-4 个服务（采集 / 分析 / 运营 / 管理后台）
- 跑顺后再细拆，避免过度拆分

### 6. 数据生命周期管理
- 行为明细 24 个月
- 聚合数据 36 个月
- 决策记录永久保存

## 六、部署架构

### 环境
- dev / test / staging / prod 四套
- Nacos 命名空间隔离
- 同一镜像不同配置

### K8s 部署
- 命名空间：`analytics-platform`
- Deployment + Service + Ingress
- ConfigMap + Secret
- HPA 按 CPU + QPS
- PDB 保证可用性

### CI/CD
- GitLab CI / Jenkins
- 多阶段构建（lint → test → security-scan → build → deploy）
- Helm Chart + Argo CD GitOps
- 蓝绿 / 金丝雀发布

### 监控告警
- Prometheus + Alertmanager
- SkyWalking APM
- ELK 日志聚合
- 飞书 / 钉钉机器人推送
