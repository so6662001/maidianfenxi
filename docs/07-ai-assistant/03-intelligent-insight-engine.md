# 智能洞察引擎产品方案

## 一、四层架构 + 反馈层

```
┌──────────────────────────────────────────────────────────────┐
│ L4 学习层  反馈收集 → 调阈值 / 调推荐策略 / 调归因权重         │
├──────────────────────────────────────────────────────────────┤
│ L3 行动层  推送通道 + 决策待办池 + 一键行动按钮                │
├──────────────────────────────────────────────────────────────┤
│ L2 智能层  LLM 摘要 + 决策建议生成 + 自然语言报告              │
├──────────────────────────────────────────────────────────────┤
│ L1 分析层  异动检测 + 维度归因 + 因果分析                      │
├──────────────────────────────────────────────────────────────┤
│ L0 数据层  指标平台 + 行为明细 + 业务上下文                    │
└──────────────────────────────────────────────────────────────┘
```

## 二、能力详解

### 能力 1 · 异动检测

| 算法 | 适用 |
|---|---|
| 阈值规则（绝对/同比/环比） | 明确告知"低于 X 报警" |
| STL 分解 + 3σ | 有季节性指标 |
| Prophet | 复杂趋势 + 多季节性 |
| Isolation Forest | 多维联合异常 |
| Z-Score on Residual | 实时流式检测 |

**关键产品设计**：
- 每个指标有"敏感度"档位（高/中/低），用户可调
- 静默时段（夜里不推非紧急）
- 假期/活动日历自动忽略（双 11 不告警）
- 异常去重（同一原因合并为 1 条）

### 能力 2 · 智能归因

```
异动指标 → 多维下钻 → 找贡献最大子集 → 业务上下文关联 → 输出归因报告

技术路线（递进）：
  V1: 维度下钻 + Adtributor（Microsoft 论文）
  V2: 因果森林 / DoWhy 
  V3: 多指标联合归因 + 时间窗口对齐
  V4: LLM 整合多源信号（变更日志/客诉/监控告警）
```

**归因报告样例**：

```
🚨 AI-写作 DAU 异常下降 23%（2026-05-23 09:13）

根因分析（按贡献度）：
  1. 新版本 v2.3.1 上线（5/22 22:00）→ 贡献 65%
     · 响应延迟 P99 800ms → 2.8s
     · 用户放弃率 5% → 28%
  2. iOS 端崩溃率上升 → 贡献 22%
  3. 华南节点网络抖动 → 贡献 13%

关联事件：
  · GitHub PR #4521（性能改动）
  · 客服工单 12 条（5/23 早上集中报响应慢）
  · 监控告警 3 条（5/23 02:00 起延迟告警）

建议动作：
  A) 立即回滚 v2.3.1（可恢复 80% DAU）
  B) 灰度暂停 + 紧急修复（24h 内）
  C) 全量监控观察（不建议）
```

### 能力 3 · 决策建议生成

```
触发条件                   → 候选建议库                → LLM 个性化包装
─────────────────────       ─────────────────         ─────────────
- 异动类型                  - 历史相似案例的解法        - 结合上下文
- 影响范围                  - PM/CS Playbook 库         - 自然语言生成
- 紧急程度                  - 行业最佳实践              - 1/2/3 排序
- 历史相似事件              - 业务规则库                - 风险标注
```

**关键设计**：
- 至少 3 个备选方案（A/B/C），不要单一答案
- 每方案标注：预期效果、风险、所需资源、相似案例引用
- 置信度分级（高/中/低）
- 选择后记录"采纳/拒绝"，反哺学习

### 能力 4 · 智能推送

| 通道 | 适用 |
|---|---|
| 站内 + 决策待办池 | 默认 |
| 企微 / 钉钉 | 紧急 |
| 邮件 | 日报/周报/月报 |
| 电话 / SMS | 仅 P0 灾难 |

**防过载**：
- 单用户每天 ≤ 7 条
- 同问题 24h 去重
- 用户可关闭某类（带"为什么"反馈）
- 重要度 < 阈值进"摘要日报"

### 能力 5 · 反馈学习

```
推送 → 用户操作（处理/忽略/反馈"误报"/"不重要"）
       ↓
       记录反馈库
       ↓
       周度自动调优：
         · 被忽略指标 → 提高阈值
         · 被处理指标 → 降低阈值
         · 用户认可的归因维度 → 加权
         · AI 建议采纳率作为 Prompt 优化信号
```

## 三、调度与触发

| 类型 | 频率 |
|---|---|
| 实时指标异动 | 每 5 分钟扫描 |
| 离线指标异动 | 每日 06:30 |
| 战略假设进度 | 每周一 09:00 |
| 复盘到期提醒 | 每日 09:00 |
| 早报推送 | 每日 08:00 |
| 周报推送 | 每周一 09:00 |
| 月报推送 | 每月 1 号 09:00 |

## 四、评估指标

| 指标 | 目标 |
|---|---|
| 异动检测召回率 | ≥ 90% |
| 异动检测误报率 | ≤ 10% |
| 归因准确率（人工抽检） | ≥ 80% |
| 推送处理率 | ≥ 70% |
| 推送被标"误报/不重要"率 | ≤ 15% |
| AI 建议采纳率 | ≥ 40% |
| 平均决策时长（推送→决策） | ≤ 4h（紧急）/ 2 天（重要） |

## 五、上线节奏

| 阶段 | 内容 |
|---|---|
| **第一阶段** | 阈值规则 + 简单归因 + 站内推送 |
| **第二阶段** | STL/Prophet + 维度下钻 + LLM 摘要 + 企微推送 |
| **第三阶段** | 因果归因 + 决策建议库 + 一键行动闭环 |
| **第四阶段** | 反馈学习 + 个性化 + 跨场景知识沉淀 |

## 六、技术实现

| 模块 | 选型 |
|---|---|
| 调度 | XXL-Job + Flink CEP |
| 异动算法 | Python micro-service（Prophet / sklearn）+ Java Client |
| 归因 | Adtributor 实现（Java） |
| LLM | LangChain4j + GPT-4 |
| 推送 | 复用触达中心 |
| 反馈 | Redis + 离线分析 |
