# 业务背景与目标

## 公司业务全景

### SaaS 产品线
- 形态：订阅制企业级软件
- 客户：B2B 企业（中小 + 大客户）
- 收费：按 Seat / 模块 / 年付订阅
- 关键指标：NRR、续约率、ARR、Adoption

### AI 产品线
- 形态：基于 LLM 的智能助手（如写作、Agent、对话等）
- 客户：B2B + B2C 混合
- 收费：免费 + 订阅（按 Token / 高级模型）
- 关键指标：价值采纳率、单次毛利、TTFV

### 平台产品线
- 形态：双边市场（B2B 撮合）
- 双边角色：
  - **商家（供给侧）**：发布库存、响应询盘、报价
  - **买家（需求侧）**：搜索库存、留线索、发起询盘
- 平台撮合：在线查询 + 询价报价 + 线索分发
- 收费：
  - 会员费（商家分等级）
  - 流量费（商家购买曝光包）
- 关键指标：24h 询盘响应率、撮合成功率、GMV、双边留存

## 当前痛点

### 总产品经理（你）的痛点
1. 无法快速判断哪个产品/功能值得投入
2. PM 团队的判断质量难以客观评估
3. 战略决策依赖直觉，缺乏数据支撑
4. 资源分配缺乏 ROI 量化依据

### 各产品 PM 的痛点
1. 不知道用户用了哪些功能、用得多深
2. 查询类功能用户填什么参数、查出多少结果不可见
3. 功能设计质量缺乏量化评估手段
4. 无法快速识别"鸡肋功能"和"明星功能"

### 运营团队的痛点
1. 用户分群需要技术配合，效率低
2. 触达通道分散（邮件/短信/Push/企微），数据不通
3. 缺乏自动化 Journey 编排
4. 实验结果分析依赖数据团队

### 客户成功（CSM）的痛点
1. 客户健康分难以量化
2. 流失风险预警滞后
3. 没有标准化的客户挽留 Playbook

### 数据团队的痛点
1. 各产品口径不一，反复对账
2. 业务方提需求多，自助率低
3. 指标定义散落，无法治理

## 中台要解决的核心问题

| 痛点 | 中台解决方案 |
|---|---|
| 决策依赖直觉 | 5 张战略看板 + 智能洞察 + 决策追溯库 |
| PM 判断质量不可见 | S-3 PM 效能榜，基于历史决策达成率 |
| 用户行为不透明 | 完整埋点 + 单功能健康度 + 查询参数分析 |
| 三类产品模型混淆 | 3 套业务模型（SaaS LCM / AI 单位经济 / 平台双边流动性） |
| 运营效率低 | 嵌入式组件 + Journey 编排 + 37 Playbook |
| 数据口径不一 | 指标平台一元化 |
| 业务方接入难 | OpenAPI + Vue3 组件库 + 微前端 |

## 业务目标（量化）

| 维度 | 目标 |
|---|---|
| 总产品经理决策时间 | 每个重要决策准备时间从 2 天 → 2 小时 |
| 业务接入数 | V1 末 ≥ 5 个业务系统接入 |
| 用户增长效率 | LTV/CAC 提升 ≥ 30% |
| 流失率 | 同比下降 ≥ 15% |
| 决策达成率 | 复盘"达成 + 部分达成" ≥ 75% |
| ROI | 第 1 年 ≥ 2x，第 3 年 ≥ 10x |
