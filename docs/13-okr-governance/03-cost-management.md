# 成本管理

## 一、成本构成

```
中台总成本
├─ 人力（占 ~60%）
│   ├─ 中台团队 20-30 人
│   └─ 业务方接入支持
├─ 基础设施（占 ~25%）
│   ├─ K8s 节点（计算）
│   ├─ 数据库（MySQL / ClickHouse / Redis / ES）
│   ├─ 消息队列（Kafka）
│   ├─ 存储（OSS / EBS）
│   └─ 网络
├─ 第三方服务（占 ~10%）
│   ├─ LLM API（OpenAI / Claude / 通义千问）
│   ├─ 邮件 / 短信 / Push
│   ├─ APM / 日志 SaaS
│   └─ 监控 SaaS
└─ 工具与许可（占 ~5%）
    ├─ IDE / Git 仓库
    ├─ Sentry / Snyk / Sonar
    └─ 设计工具（Figma 等）
```

## 三、成本优化策略

### 1. 基础设施优化

**容器资源**
- 准确设置 requests / limits（避免预留浪费）
- HPA 弹性扩缩（按 CPU + QPS）
- 夜间自动缩容（非核心服务）
- 使用 Spot 实例（非关键负载）

**数据库**
- 冷热分层（30 天热 → 冷归档）
- 数据生命周期管理（TTL 自动清理）
- 读写分离 + 索引优化
- 慢查询治理

**存储**
- 大日志压缩
- 归档到对象存储
- 删除无用快照

### 2. LLM 成本优化（重点）

详见 [AI 模型治理](../07-ai-assistant/04-model-governance.md)。

核心策略：
- **模型路由**：简单请求用小模型（节省 50%）
- **语义缓存**：相似请求复用结果（节省 20%）
- **输出长度控制**：默认精简（节省 15%）
- **批量处理**：合并请求
- **Provider 切换**：选择性价比高的

预算告警：
- 月预算 50% → 通知
- 月预算 80% → 警告 + 评审
- 月预算 100% → 限流 / 降级

### 3. 第三方服务

- 邮件/短信：按需用，避免无效触达
- APM：分层使用（关键服务用高级版，非关键用基础版）
- 工具：定期审计，下线无人用的

## 四、成本可见性

### Grafana 成本看板

```yaml
看板 1：成本总览
- 月度总成本 + 同环比
- 按类型拆分（人力/基础设施/第三方）
- 按服务拆分

看板 2：基础设施成本
- 按 K8s 命名空间
- 按节点池
- CPU/内存利用率（找闲置）

看板 3：LLM 成本
- 按模型 / 场景 / 用户
- Token 消耗趋势
- 路由命中率
- 缓存命中率

看板 4：业务成本
- 按业务方接入数
- 按指标查询数
- 按 Playbook 执行数
- 单 ROI（成本 / 价值）
```

### 成本告警

```yaml
- alert: InfraCostSpike
  expr: sum(rate(infra_cost_yuan[1d])) > avg_over_time(...[7d]) * 1.5
  severity: P1
  
- alert: LLMCostSpike
  expr: sum(rate(llm_cost_yuan[1h])) > ...
  severity: P1

- alert: K8sResourceUnderutilized
  expr: avg(cpu_usage) < 0.2
  for: 7d
  severity: P2
  description: K8s 资源利用率持续低于 20%，建议缩容
```

## 五、成本分摊

### 按业务方分摊

- 数据采集：按事件量
- API 调用：按调用次数
- 嵌入组件：按 PV
- LLM：按 Token

分摊报告：每月发给业务方负责人，用于其 OKR 考核。

### 按产品线分摊

- SaaS / AI / 平台 各产品线消费多少中台资源
- 用于 S-1 产品组合矩阵的"ROI"计算

## 六、ROI 量化

### 中台 ROI 公式

```
ROI = 中台产出价值 / 中台总投入

产出价值：
+ 触达带来的增量收入
+ 流失挽回节省
+ 决策效率提升节省（按工时折算）
+ 错误决策避免（事后复盘）
+ 用户增长效率提升

总投入：
人力 + 基础设施 + 第三方 + 工具
```

### 季度 ROI 评估

每季度评估并报告给高管：
```
Q1 总投入：¥X
Q1 产出价值：¥Y
ROI：Y/X

亮点：
- ...

待优化：
- ...
```

### 目标 ROI

- 第 1 年 ≥ 2x
- 第 2 年 ≥ 5x
- 第 3 年 ≥ 10x

## 九、应急成本控制

### LLM 成本失控

```
触发：月预算 80% 提前 1 周用完
   ↓
立即措施：
1. 切换到更便宜的模型
2. 启用更严格的限流
3. 关闭非核心场景
4. 紧急排查（是否被刷）
   ↓
事后：
- 根因分析
- 流程改进
- 预算调整
```

### 基础设施成本失控

```
触发：节点资源使用突增
   ↓
立即措施：
1. 找到资源消耗大户（Pod / 服务）
2. 评估是否合理（业务增长 vs 异常）
3. 异常 → 排查代码
4. 合理 → 申请扩容预算
```

## 十一、成本 KPI

| 指标 | 目标 |
|---|---|
| 月预算执行 | ±10% |
| LLM 成本/会话 | 按场景预算 |
| K8s 资源利用率 | ≥ 60% |
| ROI | 第 1 年 ≥ 2x |
| 业务方接入数 / 中台总投入 | 持续上升 |

## 十二、与战略的联动

- 中台 ROI < 预期 → 调整中台投入策略
- 中台 ROI 优秀 → 加大投入，扩展能力
- 单业务方 ROI 低 → 评估是否继续支持
- 单 Playbook ROI 低 → 优化或下线
