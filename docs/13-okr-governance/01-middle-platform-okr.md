# 中台自身 OKR 与成熟度模型

## 一、中台北极星指标

> **"被多少业务方采纳并产生可量化价值"**

```
NSM = (月活业务方数 × 月活业务方决策数 × 决策达成率) / (中台总投入成本)

= "每元中台投入支撑的成功决策数"
```

## 二、季度 OKR 框架

### O1 · 让中台被广泛采纳（覆盖度）

| KR | 季度目标 | 度量方式 |
|---|---|---|
| KR1.1 | 接入业务系统数 ≥ 8 个 | API/SDK/嵌入组件接入统计 |
| KR1.2 | 月活业务方用户 ≥ 500 人 | 助理 + 看板 + 组件 UV |
| KR1.3 | 中台日活高管 ≥ 15 人 | 总裁/总 PM/CFO 等 |
| KR1.4 | 嵌入组件被使用次数 ≥ 10万次/月 | 组件埋点 |

### O2 · 提升决策质量（价值）

| KR | 季度目标 | 度量方式 |
|---|---|---|
| KR2.1 | 决策追溯库登记数 ≥ 300 个 | 决策追溯库统计 |
| KR2.2 | 重要决策（P0/P1）登记覆盖率 ≥ 80% | 抽样审计 |
| KR2.3 | 决策达成率 ≥ 65% | 复盘结果 |
| KR2.4 | AI 建议被采纳率 ≥ 40% | 助理反馈 |
| KR2.5 | 决策助理对话满意度 ≥ 75% | 用户 👍 率 |

### O3 · 增长效率提升（业务结果）

| KR | 季度目标 | 度量方式 |
|---|---|---|
| KR3.1 | 中台支撑的 Playbook 数 ≥ 25 个 | 上线统计 |
| KR3.2 | Playbook 总 ROI ≥ 5x | 触达增量收益 / 触达成本 |
| KR3.3 | 用户流失率同比下降 ≥ 15% | 业务指标 |
| KR3.4 | LTV/CAC 提升 ≥ 10% | 业务指标 |

### O4 · 中台自身健康（质量）

| KR | 季度目标 | 度量方式 |
|---|---|---|
| KR4.1 | 埋点覆盖率 ≥ 95% | 核心事件覆盖 |
| KR4.2 | 指标口径冲突 ≤ 5 个 | 治理统计 |
| KR4.3 | 服务可用性 ≥ 99.9% | SLA |
| KR4.4 | 数据新鲜度 P99 ≤ 4 小时 | T+0/T+1 监控 |
| KR4.5 | 看板加载性能 P95 ≤ 3s | APM |

## 三、成熟度模型（5 级）

| 级别 | 名称 | 特征 | 关键指标 |
|---|---|---|---|
| L1 | **初创期** | 数据散乱、靠 SQL 拉数 | 接入业务方 ≤ 2，无指标平台 |
| L2 | **基础期** | 看板搭建、统一埋点 | 接入 ≤ 5，核心指标统一 |
| L3 | **运营期** | 分群+触达+实验闭环 | Playbook ≥ 10，AB 跑通 |
| L4 | **决策期** | 决策追溯 + 智能洞察 | 决策登记 ≥ 200/季，AI 采纳 ≥ 40% |
| L5 | **智能期** | 对话式 BI、Agent 化决策 | 助理日活高管 ≥ 80%，自动决策能力 |

每年评估 1 次，组织内部评分 + 外部顾问审计。

## 四、中台 ROI 量化（年度董事会汇报）

```
中台投入：
  · 人力：N1 × 12 月 × 人月成本 = ¥A
  · 基础设施：¥B
  · 工具采购：¥C
  总投入：¥S

中台产出（量化）：
  · 触达带来的增量收入：¥X1
  · 流失挽回节省：¥X2
  · 决策效率提升节省（人时）：¥X3
  · 错误决策避免：¥X4
  · 用户增长效率提升：¥X5
  总产出：¥T

ROI = T / S
```

**目标**：第 1 年 ≥ 2x，第 2 年 ≥ 5x，第 3 年 ≥ 10x

## 六、中台团队组织设计

```
中台负责人 (向总产品经理直接汇报)
   │
   ├── 中台 PM 组 (3-5 人)
   │     ├── 数据 PM × 2-3 (口径治理、指标平台)
   │     ├── AI 应用 PM × 1 (助理、智能洞察)
   │     └── 组件 PM × 1 (嵌入组件、SDK)
   │
   ├── 数据工程 (5-8 人)
   │     ├── 采集 / 数仓 / 计算
   │     └── 实时 / 离线
   │
   ├── 应用开发 (5-8 人)
   │     ├── 前端 (Vue3 / 微前端 / 组件库)
   │     ├── 后端 (Java / Spring Cloud)
   │     └── AI 工程 (LLM 应用)
   │
   ├── 数据治理 (2-3 人)
   │     ├── 元数据 / 质量 / 权限
   │     └── 合规 / 隐私
   │
   └── 运营 / BP (3-5 人)
         ├── 接入大使 (协助业务方接入)
         ├── 培训 / 文档
         └── 数据分析师 (协助业务方做分析)

总规模建议：20-30 人（视公司规模）
```

## 七、风险与缓解

| 风险 | 缓解 |
|---|---|
| 采纳风险 | KR 与业务方 OKR 强绑定；高管亲自使用；接入大使制度 |
| 数据信任 | 指标平台一元化；数据治理委员会季度评审 |
| AI 失控 | 二次确认 + 决策人拍板原则 + 置信度透明 |
| 安全合规 | 行级 + 字段级权限；审计全留痕；隐私评估 |
| 技术债 | 季度技术债清理日；架构评审机制 |
| 组织 | BP 制度；业务方满意度 NPS；定期共创会 |
| ROI 不达预期 | 阶段性 ROI 评估；MVP 先行；高 ROI 场景优先 |

## 八、与业务 OKR 联动

```
公司年度 OKR
   ↓
中台 OKR（支撑公司 OKR）
   ↓
中台季度 OKR
   ↓
中台双周冲刺
   ↓
每周状态同步
   ↓
季度复盘 + 调整
```
