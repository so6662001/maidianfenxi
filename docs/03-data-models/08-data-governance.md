# 数据治理详细方案

## 一、数据治理五大支柱

```
1. 元数据管理：事件 / 指标 / 标签 / 表 / 字段 统一注册
2. 数据质量：质量规则 + 监控 + 异常处置
3. 数据血缘：从源到应用的关系图谱
4. 数据生命周期：分级 + 保留 + 归档 + 删除
5. 数据合规：分类分级 + 权限 + 审计 + 隐私
```

## 二、数据治理委员会

### 组织架构

```
数据治理委员会（季度评审）
   ├─ 主席：总产品经理 / CDO
   ├─ 成员：数据 PM × 3 + 各产品线 PM 代表 + 法务 + 安全
   └─ 执行：数据治理团队（2-3 人）
```

### 职责
- 制定数据规范
- 评审重大指标 / 事件变更
- 处理数据质量重大问题
- 推动跨部门数据共享
- 合规审查

## 三、元数据管理

### 元数据中心

统一管理：
- 事件元数据（见 07-event-tracking-spec.md）
- 指标元数据（见 04-metrics-dictionary.md）
- 标签元数据
- 数据库表/字段
- 数据集 / 报表

### 元数据条目必填

| 字段 | 说明 |
|---|---|
| code | 唯一标识 |
| name | 中文名 |
| description | 业务定义 |
| owner | 责任 PM + 责任数据 PM |
| status | 草稿/启用/废弃 |
| version | 版本号 |
| created_at / updated_at | |
| lineage | 上下游关系 |
| classification | 数据分级（公开/内部/敏感/极敏感） |
| retention | 保留策略 |
| compliance | 合规标签（PIPL / GDPR / 出境） |

### 元数据变更流程

```
1. 提交变更申请（描述 + 影响评估）
2. 责任人初审
3. 数据治理团队复审
4. 高敏变更：委员会评审
5. 通知业务方
6. 灰度发布（如果有兼容性影响）
7. 元数据版本号 +1
8. 归档变更记录到决策追溯库
```

## 四、数据质量

### 质量维度（DAMA 6 维）

| 维度 | 说明 |
|---|---|
| **完整性** | 必填字段不能缺 |
| **唯一性** | 主键不重复 |
| **准确性** | 数值符合业务逻辑 |
| **一致性** | 跨系统口径一致 |
| **及时性** | 数据按 SLA 到达 |
| **有效性** | 字段值在合法范围 |

### 质量规则

#### 表级规则
```yaml
table: t_subscription
rules:
  - type: count_check
    expression: count > 0
    severity: critical
  - type: row_count_delta
    expression: abs(today - yesterday) < 0.5 * yesterday
    severity: warning
```

#### 字段级规则
```yaml
table: t_subscription
field: amount
rules:
  - type: not_null
    severity: critical
  - type: range
    min: 0
    max: 10000000
    severity: critical
  - type: distribution
    method: zscore
    threshold: 3
    severity: warning
```

#### 业务规则
```yaml
rule: NRR 合理范围
expression: NRR between 0.5 and 2.0
severity: critical
on_violation: 告警 + 自动 kill 查询
```

### 质量监控

```
每日 06:30 跑质量检查
   ↓
对每张表 / 字段 / 业务规则执行
   ↓
异常 → 告警（按 severity 分级）
   ├─ Critical → 自动阻断下游消费 + 通知值班
   ├─ Warning → 通知数据 PM + 记录
   └─ Info → 报表统计
   ↓
质量看板：实时质量分（按表 / 业务域）
```

### 质量分

```
表质量分 = 通过规则数 / 总规则数 × 100
业务域质量分 = 该域所有表质量分均值
公司整体质量分 = 各业务域加权
```

目标：
- 核心表质量分 ≥ 95%
- 整体质量分 ≥ 90%

## 五、数据血缘

### 血缘图谱

```
源系统（业务库 / SDK 上报）
   ↓
ODS（原始）
   ↓
DWD（明细）
   ↓
DWS（汇总）
   ↓
ADS（应用）
   ↓
看板 / 报表 / API / 嵌入组件
```

### 血缘元数据

每个数据节点记录：
- 上游：来源（表 / 接口 / 文件）
- 下游：被谁消费（看板 / 指标 / API）
- 处理逻辑：ETL SQL / Flink Job
- 责任人

### 血缘工具
- DataHub / Apache Atlas / Open Metadata
- 或自研：基于 SQL 解析 + Flink 作业元数据

### 血缘用途
- 影响分析：某字段下线影响哪些下游
- 故障定位：下游数据异常追溯到上游
- 数据资产盘点

## 六、数据生命周期管理

### 数据分级

| 级别 | 定义 | 示例 |
|---|---|---|
| L1 公开 | 任何人可见 | 帮助文档 |
| L2 内部 | 公司内可见 | 公司级 KPI |
| L3 敏感 | 受限角色可见 | 客户名单 / 订单金额 |
| L4 极敏感 | 严格授权 | 个人身份证 / 银行卡 |

### 保留策略

| 数据 | 热存 | 冷存 | 归档/删除 |
|---|---|---|---|
| 行为明细（dwd） | 6 月 | 24 月 | 删除 |
| 聚合数据（dws） | 24 月 | 36 月 | 永久（合规允许） |
| 元数据 | 永久 | — | — |
| 决策记录 | 永久 | — | — |
| 操作日志 | 6 月 | 24 月 | 删除 |
| 审计日志 | 180 天 | 1 年 | 删除 |
| LLM 对话 | 3 月 | 12 月 | 删除（PII 脱敏） |
| 个人信息 | 跟随用户活跃 | 30 天 | 删除（PIPL） |

### 自动归档/删除

```
XXL-Job 每日跑：
  ├─ 扫描过期数据
  ├─ 热存 → 冷存（OSS / 归档存储）
  ├─ 冷存 → 删除（已过保留期）
  └─ 留痕日志（审计）
```

### 用户主动删除（PIPL Right to Delete）

```
用户提交"删除我的数据"请求
   ↓
1. 验证身份
   ↓
2. 暂停该用户数据收集
   ↓
3. 30 天内删除：
   - 用户主表
   - 关联行为数据
   - 关联标签
   - 关联分群（移出）
4. 保留合规必要数据（如已开发票，合规要求保留）
   ↓
5. 通知用户已完成
   ↓
6. 审计留痕
```

## 七、数据合规

### 合规清单

- **个人信息保护法（PIPL）** —— 中国主要适用
- **数据安全法** —— 数据出境评估
- **网络安全法** —— 网络运行安全
- **GDPR** —— 如有欧盟用户
- **CCPA** —— 如有加州用户
- **行业法规** —— 金融 / 医疗等

### 合规要点

1. **告知 + 同意**：注册时明确告知 + 用户主动勾选
2. **最小必要**：只收集业务必要数据
3. **目的限制**：不超出告知目的使用
4. **数据主体权利**：访问 / 导出 / 删除 / 撤销同意
5. **第三方共享**：必须告知并获得同意
6. **跨境传输**：单独评估 + 安全协议
7. **数据泄露通报**：72 小时内通报监管

### 合规接口（必须提供）

```
GET    /api/privacy/my-data          # 数据访问
POST   /api/privacy/export           # 数据导出
POST   /api/privacy/delete           # 数据删除（GDPR Right to Delete）
GET    /api/privacy/access-log       # 我的数据被访问记录
POST   /api/privacy/consent/revoke   # 撤销同意
POST   /api/privacy/consent/update   # 更新同意范围
```

### PIA 评估

每个新功能上线前必须输出 PIA 报告：
- 数据收集清单
- 使用目的
- 存储期限
- 访问权限
- 跨境情况
- 风险评估 + 缓解措施
- 法务签字

模板由法务团队提供。

## 八、数据资产门户

提供给数据 PM 和高级业务用户：
- 数据目录（所有表 / 字段 / 指标 / 标签）
- 血缘图谱
- 数据质量报告
- 元数据检索（语义搜索）
- 申请数据访问权限
- 数据使用 SLA 查询

## 九、跨产品 / 跨租户数据共享

### 默认隔离

- 不同租户数据完全隔离
- 不同产品线数据按需共享（OneID 关联）

### 共享审批

- 申请人提交共享需求
- 数据 Owner 审批
- 数据治理团队复审
- 配置共享视图（不暴露明细，只暴露聚合）

## 十二、治理实施节奏

### Phase 1（MVP）
- 元数据中心（事件 / 指标）
- 基础数据质量监控
- 核心合规接口

### Phase 2（V1）
- 完整元数据（含表 / 字段 / 血缘）
- 数据质量规则全覆盖
- 数据资产门户

### Phase 3（V2）
- 自动血缘
- 自助申请权限
- 智能数据发现
