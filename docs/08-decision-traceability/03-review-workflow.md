# 决策追溯库 · 自动复盘流程

## 一、复盘时间轴

```
T+0    决策登记，数据快照冻结
T+7    若 P0 决策，发送"7 天健康检查"轻量复盘
T+30   第一次正式复盘提醒（自动生成初稿）
T+60   第二次复盘提醒
T+90   第三次复盘提醒
T+180  最终复盘 + 封板 + 知识沉淀
```

## 二、自动复盘初稿生成流程

```
触发节点到达
   ↓
系统自动调取：
   · 决策时数据快照
   · 当前最新数据
   · 关联指标的实际变化
   · 关联实验/分群/触达的结果数据
   ↓
对比生成"实际 vs 预期"差异表
   ↓
LLM 撰写复盘初稿：
   · 进度评估（达成 / 部分达成 / 未达成）
   · 实际效果与预期偏差分析
   · 可能原因（多假设）
   · 后续建议
   ↓
推送给复盘负责人（站内 + 邮件 + 待办）
   ↓
负责人收到提醒，进入复盘编辑页
   ↓
基于 AI 初稿微调 + 补充经验沉淀
   ↓
提交复盘
   ↓
若状态 = 失败 → 自动触发"决策方法论根因分析"
   ↓
归档 + 知识标签 + 关联 PM 效能榜
```

## 三、复盘表单字段

```yaml
review_id: 自动
decision_id: 关联
review_phase: 30d / 60d / 90d / 180d / adhoc

actual_impact:
  - metric: <KPI>
    expected: <预期>
    actual: <实际>
    deviation: <偏差%>

deviation_analysis: 富文本（AI 草稿）
conclusion: ✅ 达成 / ⚠️ 部分达成 / ❌ 未达成 / 🔄 进行中
lessons_learned: 富文本（鼓励 3 条以内）
knowledge_tags: 多选
shareable: 公司案例库 / 部门 / 仅自留
followup_actions: 列表

reviewed_by: 用户
reviewed_at: 时间
```

## 四、复盘自动调取的指标对应表

| 决策类型 | 自动调取指标 |
|---|---|
| SaaS 业务决策 | NRR、续约率、客户健康分变化、目标客户群行为 |
| AI 业务决策 | 价值采纳率、单次毛利、点踩率、能力缺口指标 |

| 应急决策 | 受影响指标恢复曲线 |

## 五、知识沉淀与反哺

### 1. 反哺智能洞察引擎

```
决策追溯库累积 100+ 决策 → 训练"决策模式识别"
  · 哪类异动用哪类 Playbook 成功率高？
  · 哪类客户在哪类干预下回流？
  → AI 建议引擎更精准
```

### 2. 反哺 Playbook 优化

```
单 Playbook 累计执行 N 次 → 自动统计：
  · 平均 ROI
  · 不同分群效果差异
  · 失败案例共性
  → 自动建议 Playbook 改进点
```

### 3. 反哺指标平台

```
某指标 N 次决策中未被使用 → 候选下线
某指标 N 次决策中频繁查询 → 优先优化性能、加入仪表盘
```

### 4. 反哺 S-3 PM 效能榜

```
每个决策关联到决策人
  → 个人决策准确率自动计算
  → 个人擅长决策类型自动归类
  → 反哺 S-3 排名
```

### 5. 反哺战略假设追踪

```
战略决策记录 → 关联到 S-4 假设
  → 假设进展自动更新
  → 假设偏离时自动告警
```

## 六、决策案例库

随时间积累形成"组织决策案例库"：

```
案例库结构：
  ├── 按决策类型分（产品/资源/战略/组织/应急）
  ├── 按业务模型分（SaaS/AI/平台/跨模型）
  ├── 按结果分（成功/部分成功/失败）
  ├── 按知识标签分（流失挽留/供需平衡/模型优化...）
  └── 全文检索 + 语义搜索

价值：
  · 新人入职：3 天内可读完"过去 12 月 50 个关键决策"
  · 决策助理：做新决策时自动检索 3-5 个相似案例参考
  · 季度评审：自动产出"决策方法论复盘报告"
  · 一年后：拥有公司最值钱的资产——决策记忆
```

## 七、与决策助理深度联动

### 检索历史相似决策示例

```
你：我打算砍掉 AI-翻译产品，帮我分析

🤖：📚 检索到 3 个相似决策案例：

    1) 2024 Q2 砍掉"邮件营销产品" ✅ 成功
       决策依据：连续 3 季度营收下滑 + ROI < 1x
       结果：节省 200 人月，转移至 AI 团队
       关键经验：必须提前 60 天通知客户 + 提供迁移工具
    
    2) 2023 Q4 转型"老版 CRM" ⚠️ 部分成功
       决策依据：用户流失加速
       结果：转型成本超预期 30%
       关键经验：转型预算容易低估，留 50% buffer
    
    3) 2023 Q1 砍掉"旧版考勤" ❌ 商誉受损
       决策依据：维护成本高
       结果：用户群体激烈反弹
       关键经验：5 年+老客户敏感产品慎砍
    
    💡 基于历史，我的建议：场景 A
    （详细分析略）
    
    要按场景 A 启动决策流程？
```

## 八、"反逃避机制"

- 复盘到期未做 → 第 1 天提醒、第 3 天升级到上级、第 7 天列入红色待办
- 部门复盘完成率纳入部门 OKR
- 失败决策不丢人，**逃避复盘才丢人**（文化建设）
